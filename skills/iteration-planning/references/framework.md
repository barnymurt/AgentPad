# Iteration Planning Framework

## Prioritization Approaches

### 1. RICE Scoring

Evaluate each idea on four dimensions:

- **Reach:** How many users will this affect?
- **Impact:** How much will this improve the user experience?
- **Confidence:** How sure are you about the estimates?
- **Effort:** How much work is required?

Score = (Reach x Impact x Confidence) / Effort

### 2. MoSCoW Method

Categorize items into:

- **Must have:** Critical for success
- **Should have:** Important but not critical
- **Could have:** Nice to have
- **Won't have:** Not this iteration

### 3. ICE Scoring

Simpler than RICE:

- **Impact:** How much will this help?
- **Confidence:** How sure are you?
- **Ease:** How easy is it to build?

Score = Impact x Confidence x Ease

### 4. Opportunity Scoring

For existing products with data:

- **Satisfaction impact:** Will users like this?
- **Usage impact:** Will this get used?
- **Business impact:** Will this help the business?

---

## How to Choose

| Situation | Recommended Approach |
|-----------|---------------------|
| Early stage, no data | MoSCoW or ICE |
| Growing product | RICE |
| Data-driven company | Opportunity scoring |
| Quick decisions | ICE |

## Input Analysis Process

### Step 1: Aggregate User Feedback

Group feedback into themes:

- Theme name
- How many times mentioned
- Sentiment (positive/negative)
- Suggested solution (if any)

### Step 2: Analyze Metrics

For each metric:

- Current value
- Trend (improving/declining/flat)
- Benchmark comparison
- What this suggests

### Step 3: Identify Patterns

Look for:
- Repeated requests (many users want same thing)
- Pain points (frustration signals)
- Usage gaps (features not used)
- Drop-off points (users leaving)

### Step 4: Map to Solutions

Connect insights to potential features:

| Insight | Potential Feature |
|---------|-------------------|
| Users asking for X | Feature for X |
| High drop-off at Y | Fix Y experience |
| Feature Z rarely used | Improve or remove Z |

## Decision Framework

### When Metrics Conflict

Sometimes metrics point in different directions. For example:
- Engagement is UP but retention is DOWN

**How to resolve:**

1. Identify which metric matters more for your business
2. Look for root cause (is one driving the other?)
3. Consider short-term vs. long-term impact
4. Ask: what would a user prefer?

### When Feedback Contradicts Metrics

Users say they want X, but data shows they don't use X.

**How to resolve:**

1. Distinguish between stated preference and revealed preference
2. Data (behavior) > stated preference (words)
3. Consider: did users try X and stop, or never try?
4. Look at usage context: maybe right feature, wrong implementation

## Early-Stage Prioritization

Without metrics, rely on:

### 1. Customer Discovery

What problems did you hear about most?

### 2. Founder Gut Check

What would you use yourself?

### 3. Quick Validation

Can you test this with 5 users before building?

### 4. Technical Feasibility

What can you actually build?

### 5. Strategic Fit

Does this align with your vision?

---

## Common Mistakes

1. **Building what users ask for** - Not all requests are equal
2. **Ignoring data** - Assuming your gut is always right
3. **Too many priorities** - Focus on 1-3 things max
4. **Not defining success** - How will you know it worked?
5. **Scope creep** - Keeping adding to iteration
