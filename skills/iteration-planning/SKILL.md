# Iteration Planning

Plan what to build next based on data, feedback, and learnings. This skill helps prioritize features and improvements that will have the biggest impact.

## When to Use This Skill

Use when:
- Deciding what to build in the next iteration
- Prioritizing backlog items
- Planning a release
- Reviewing what worked and what didn't
- Starting a new development cycle

## Workflow

### Step 1: Gather Inputs

Collect information from multiple sources:

**Metrics (if available):**
- Usage data
- Conversion rates
- Retention/churn
- User engagement
- Support tickets

**User Feedback:**
- Survey responses
- Interview insights
- Support conversations
- Feature requests

**Team Learnings:**
- Development velocity
- Technical constraints
- Technical debt
- Bugs and issues

**Strategic Context:**
- Product vision
- OKRs
- Competitive changes
- Market shifts

### Step 2: Analyze Current State

What was delivered in the last iteration?

How is it performing against benchmarks?

What worked well and what didn't?

### Step 3: Generate Priorities

Based on inputs, what should be the focus for the next iteration?

Use the prioritization framework in references.

### Step 4: Define Success Criteria

What must be true for this iteration to be successful?

## Two Paths: With Data vs. Without Data

### Path A: Products with Metrics

If you have quantitative data (usage analytics, conversion tracking, retention data), use the metrics-driven prioritization in references.

### Path B: Early-Stage / No Metrics

If you don't have metrics yet, focus on qualitative prioritization:

- User interview themes
- Support ticket patterns
- Direct customer requests
- Team observations

This is valid and often more reliable in early stages.
