# Iteration Planning Output Schema

This defines the structure of iteration planning output.

## Output Structure

```
INPUT ANALYSIS

User Feedback Themes

Theme: [Name]
Frequency: How often mentioned
Sentiment: [Positive/Negative/Mixed]
Insight: What this tells us
Potential action: [Feature or fix]

Metric Performance (if available)

Metric: [Name]
Current value: [Number]
Trend: [Improving/Declining/Flat]
Benchmark: [Industry standard]
Implication: What this suggests we do

CURRENT STATE

Last Iteration Deliverables
[What was built]

Performance vs Expectations
[How it performed]

What Worked Well
[What to keep doing]

What Didn't Work
[What to change]

NEXT ITERATION RECOMMENDATIONS

Primary Focus: [Theme/Feature]
Based on: [Data source - metrics/feedback/strategy]
Expected outcome: [What should happen]
Priority rationale: Why this first

Secondary Focus: [Theme/Feature]
Based on: [Data source]
Expected outcome: [What should happen]

DEPENDENCIES

What needs to happen first
Technical prerequisites
External dependencies

SUCCESS CRITERIA

Metric targets for this iteration:
Metric: [Name]
Target: [Number]
How we'll measure: [Method]

QUALITATIVE SUCCESS

What success looks like from user perspective

REAL-WORLD REFERENCE

Company: [Name]
Their situation: [Context]
What they did: [Specific iteration]
Result: [Outcome]
Lesson: [What we can learn]

NOTES

Any assumptions
Known risks
Open questions
```

## Quality Guidelines

- Base recommendations on actual data/feedback when available
- For early-stage products without data, note this limitation
- Provide specific metrics when possible
- Include real-world context where relevant
- Make success criteria measurable

## Output Style

Write in plain language. Avoid jargon. Make it actionable.
